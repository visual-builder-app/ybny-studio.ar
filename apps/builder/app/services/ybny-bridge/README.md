# يبني — نواة التبادل بين الاستوديوين

## الحالة

نواة **تبادل ملفات يدوي على الخادم**، وليست مزامنة تلقائية موصولة بواجهتي الإنتاج. لا يوجد زر ربط أو SSO أو مستمع حفظ مفعل. لا تستخدم `pushFiles` في عملية حفظ تلقائي.

- `bridge-converter.server.ts`: تحويل HTML/Tailwind وCSS المزوّد صراحة إلى `WebstudioFragment`، وتجهيز HTML/CSS كملفات VFS كاملة.
- `bridge-client.server.ts`: جلسة OSW خاصة بالمستخدم، طلبات إلى أصل موثوق، تحقق بيانات وحدود حجم ومهلة ومنع redirect، ثم قراءة الملفات للتحقق بعد الكتابة.
- `types.ts`: مخطط Zod لصيغة OSW المنقولة: هوية الملف والمشروع، المسار، نوعه، MIME، حجمه والتواريخ.
- لا كتابة فوق `/.PROMPT.md` أو ملفات المهارات؛ بيانات الجسر في `/.ybny/bridge.json`.
- لا اتصال بقاعدة الحسابات أو الدفع، ولا استعمال أسرار موحدة لتجاوز صلاحيات المستخدم.

## عقد المصادقة الحقيقي

المسار الحالي `/api/w/:workspaceId/sync/files` في OSW يتحقق من كوكي `osw_session` ومن عضوية مساحة العمل. لا يقبل `Authorization: Bearer YBNY_BRIDGE_SECRET`. ظهور قائمة النماذج لا يثبت صلاحية قراءة الملفات.

`sessionToken` مدخل خادم موثوق لعقد النقل الحالي؛ لا تجمعه في المحادثة ولا في حقل مكشوف بالواجهة ولا تنقله بين النطاقين يدوياً. هذا ليس تصميم المصادقة النهائية: التفعيل الإنتاجي يحتاج تدفق موافقة وربط حساب موثق ومنح وصول محدودة بالمشروع وقابلة للإبطال. لا تعدّل مصادقة OSW لتسمح للجسر بتجاوزها.

`aiBaseUrl` إعداد موثوق فقط، وليس قيمة يرسلها متصفح أو رأس HTTP. النقل يقبل HTTPS، وHTTP على loopback للاختبارات فقط.

## الحدود التي تمنع تفعيل التزامن التلقائي الآن

1. مستقبل OSW الحالي لا يوفّر معاملة ذرية لكل الدفعة أو `revision`/`If-Match`. الكتابة قد تنجح جزئياً قبل خطأ؛ نتيجة `success: false` **لا تعني rollback**. لا تعِد الطلب تلقائياً دون فحص الوجهة.
2. لا توجد آلية دمج تعديلات متزامنة أو سجل outbox وإزالة التكرار أو منع ارتداد التغييرات بين الاستوديوين.
3. تحويل HTML إلى عناصر ليس استعادة للمستند الأصلي؛ لا يضمن حفظ هوية العقد أو tokens أو الموارد أو السلوك البرمجي. النسخة الحالية ترفض script/iframe والسلوك النشط بدل ادعاء تحويل تطبيق كامل.
4. يجب تزويد CSS الخارجي الكامل صراحة؛ يعامل المحول هذا CSS بوصفه المرجع دون إضافة Tailwind preflight فوقه. دون CSS مزوّد يُستخدم تحويل Tailwind. تتحول قواعد الكلاسات المدعومة إلى أنماط قابلة للتحرير، وقد تبقى قواعد الوسوم العامة داخل تضمين CSS محفوظ، لا حقولاً في Inspector. لا يجلب المحول ملفات أو صوراً أو خطوطاً أو `@import` من الشبكة. الاستيراد الكامل للأصول وربطها بقاعدة الاستوديو عمل منفصل.
5. ترميز ملفات VFS الثنائية محفوظ في صيغة النقل، لكن سيناريو التكامل لهذه الدفعة يختبر HTML/CSS/JSON ونص التعليمات فقط، وليس كل أنواع الملفات.
6. سلامة المعاينة وCSP وعزل الكانفاس مسؤولية المستضيف أيضاً؛ بوابة الصيغة الساكنة ليست مدقق أمان شاملًا.

## اختبار مقابل الخادم الحقيقي

ملف `bridge-http-roundtrip.server.test.ts` اختبار اختياري مقابل نسخة OSW محلية في Server Mode، بمجلد بيانات مؤقت فارغ وجلسة اختبار. يحظر أي أصل غير `http://127.0.0.1:<port>`.

مثال تشغيل بعد بدء خادم OSW الاختباري:

```bash
YBNY_BRIDGE_TEST_ORIGIN=http://127.0.0.1:3196 pnpm exec vitest run --project core-server app/services/ybny-bridge
pnpm run typecheck
```

يشمل إنشاء حساب ومشروع وهميين محليين، وكتابة ملفات في VFS الحقيقي وقراءتها، والحفاظ على تعليمات AI، وإعادة تعديل HTML، والتحقق من رفض الطلب المجهول. لا يطلب توليدًا من مزود AI، ولا يستعمل حساب مستخدم حقيقي أو قاعدة إنتاج. غياب متغير الاختبار يتسبب في تخطي هذا السيناريو؛ لا تُحسب الاختبارات المتخطاة نجاح تكامل.

راجِع `docs/ybny/dual-studio-bridge-architecture.md` للحالة ومعايير التفعيل. أرقام النجاح لا تُكتب إلا من نتيجة تشغيل فعلية.
